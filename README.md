# HOME RADAR

공식 청약 공고를 자동으로 모아, 내 조건으로 **추천 / 확인 필요 / 제외** 로 갈라
"내가 실제로 신청할 수 있는 청약"을 찾는 개인용 웹앱.

로컬 전용이다. 원격 저장소와 외부 배포, 외부 알림은 아직 붙이지 않았다.

## 빠른 실행

```powershell
cd C:\minkkk\home-radar

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

.\.venv\Scripts\python.exe -m app refresh      # 공고 수집 (첫 실행 1~2분)
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8777
```

<http://127.0.0.1:8777> → 우측 상단 **내 조건** 입력 → 즉시 재판정.

```powershell
.\.venv\Scripts\python.exe -m app show        # 터미널에서 결과 보기
.\.venv\Scripts\python.exe -m app sources     # 수집원 상태 (키·robots·마지막 성공)
.\.venv\Scripts\python.exe -m unittest discover -s tests   # 테스트 85개
```

### 중복은 버리지 않고 병합한다

수집원마다 주는 항목이 다르다. 청약홈 **공식 오픈API** 는 주소·세대수·전화·
입주예정월을 주지만 **공급금액·공급면적·모집공고문 PDF 는 주지 않는다** —
그건 공개 화면 상세를 긁어야 나온다.

그래서 중복을 만나면 **신뢰도 높은 쪽을 남기고 빈 자리를 흡수되는 쪽에서
채운다**(`dedup.merge_into`). 신뢰도만 보고 버렸을 때 금액·면적이 196/200건
사라졌다. 어느 수집원에서 합쳐졌는지는 상세 화면의 '출처'에 나온다.

수집원마다 **마지막 성공 시각·건수·실패 사유**를 기록해 화면 상단에 그대로 띄운다.
하나가 죽어도 나머지는 수집된다.

### API 키 넣기

키는 **환경변수 → `.env` 파일** 순서로 읽는다. 코드에는 절대 쓰지 않는다.

**방법 1 — `.env` 파일 (권장).** 재부팅해도 남고, 서버 재시작도 필요 없다.

```powershell
cd C:\minkkk\home-radar
copy .env.example .env
notepad .env
```

파일 경로: **`C:\minkkk\home-radar\.env`**

```
LH_API_KEY=여기에_일반인증키_Decoding_붙여넣기
APPLYHOME_API_KEY=
```

`.env` 는 `.gitignore` 에 있어 커밋되지 않는다. `.env.example` 만 커밋한다.
파일 수정시각이 바뀌면 자동으로 다시 읽으므로 **서버를 재시작하지 않아도 된다.**

**방법 2 — 환경변수 (이 세션에서만).**

```powershell
$env:LH_API_KEY = "일반 인증키(Decoding)"
```

**확인:**

```powershell
.\.venv\Scripts\python.exe -m app sources
```

```
[O] LH 분양임대공고문  (공식 오픈API)
     키: 설정됨 (.env) aBcD******== (84자)
```

출력에는 **마스킹된 값만** 나온다 (앞 4자·뒤 2자·길이). 원문 키는 로그·화면·API
응답 어디에도 나가지 않는다.

#### 공통 인증키 재사용

공공데이터포털은 **계정당 인증키가 하나**다. 활용신청만 서비스별로 하고,
승인되면 같은 키로 호출한다. 그래서 서비스 전용 변수가 비어 있으면
`DATA_GO_KR_API_KEY` → `LH_API_KEY` → `APPLYHOME_API_KEY` 순으로 폴백한다
(`registry.PORTAL_KEY_FALLBACK`). **`LH_API_KEY` 하나만 넣어도 청약홈 공식
API 가 동작한다** — 2026-10-30 실측으로 확인했다.

폴백이 승인 상태를 건너뛰게 하지는 않는다. 활용신청이 안 된 서비스는
호출 단계에서 거부되고, 화면에는 그 이유가 그대로 나온다.
`python -m app sources` 는 키가 어느 변수에서 왔는지도 알려 준다.

#### Encoding / Decoding 키

포털은 같은 키를 두 가지로 보여준다.

| | 모양 | |
|---|---|---|
| 일반 인증키(**Decoding**) | `aBcD1234+/=...` | **이쪽을 권한다** |
| 일반 인증키(Encoding) | `aBcD1234%2B%2F%3D...` | 넣어도 동작한다 |

HTTP 클라이언트가 쿼리 파라미터를 다시 인코딩하므로, Encoding 키를 그대로 보내면
`+` → `%2B` → `%252B` 로 **이중 인코딩**되어 인증이 깨진다. HOME RADAR 는 키가
퍼센트 인코딩돼 있으면 보내기 전에 한 번 풀어서 이 문제를 막는다
(`app/secrets.py`, 회귀 테스트 `tests/test_secrets.py`).

#### 활용신청 범위

LH 는 **서비스별로 활용신청을 각각** 해야 한다. 하나만 승인됐으면 나머지는
`SERVICE_ACCESS_DENIED_ERROR` 가 떨어진다.

| 서비스 | 쓰임 |
|---|---|
| 15058530 공고 목록 | 공고명·지역·유형·게시일·마감일·원문링크 |
| 15057999 공고 상세 | 접수시작·마감·당첨발표일·주소·세대수 |

키가 없으면 그 수집원은 **건너뛰고 '키 없음'으로 표시**된다. 조용히 실패하지 않는다.
호출 한도 초과·미등록 키·승인 안 된 서비스는 각각 다른 안내 문구로 구분된다.

### 공개 화면 수집과 이용조건

각 사이트의 `robots.txt` 를 직접 받아 확인했다 (2026-10-30). 결과는 [NOTICE.md](NOTICE.md).

- **SH 홈페이지(i-sh.co.kr)** 는 `robots.txt` 에서 `ClaudeBot`·`GPTBot` 등 AI 에이전트를
  명시적으로 `Disallow: /` 로 막고 있다. 일반 `User-agent: *` 규칙은 해당 경로를 막지
  않지만, 사이트가 AI 에이전트를 거부했으므로 **구현하지 않고 기본값을 끔으로 뒀다.**
  판단은 사용자에게 맡긴다 (`config.yaml` 의 `sources.ish.enabled`).
- 공개 화면을 읽는 수집원은 페이지 사이에 간격(0.7초)을 두고 가볍게 읽는다.

### 중복 · 정정

- **중복 제거**: 같은 수집원에서 제목·지역·접수기간이 모두 같거나, 다른 수집원끼리
  제목·지역이 같고 접수시작이 3일 이내면 하나로 합친다. 공식 API 쪽을 남긴다.
  보수적으로 판단한다 — 잘못 합치면 실제 기회가 사라진다.
- **정정 공고 감지**: '정정공고·기간연장·공고취소·재공고·추가모집' 을 찾아 원본과 연결한다.
  `(조합원 취소분)` 같은 **공급 유형 설명은 정정으로 보지 않는다** (오탐 32건을 잡은 회귀 케이스).
- **공고 수정 추적**: 접수일·발표일·세대수·주소·금액이 바뀌면 이력으로 쌓고 화면에 띄운다.
  금액은 사람이 읽는 문자열이 아니라 **숫자**로 추적한다 (표시 형식을 바꿔도 변경으로 잡히지 않게).

## 판정 — 조건마다 따로 본다

공고 하나에 대해 조건을 **하나씩** 판정하고(`app/checks.py`), 그 모음으로 등급을 정한다.

| 조건 상태 | 뜻 |
|---|---|
| **충족** | 어떤 공고 기준이든 확실히 통과한다 |
| **미확인** | 판단할 정보가 없거나, 공고별로 기준이 달라 단정할 수 없다 |
| **불충족** | 구조적으로 지원이 안 된다 |

등급은 이 순서로 정해진다.

1. 내가 걸어둔 관심 지역·유형·분양가 필터에 걸리면 → **제외** (자격 문제와 구분해 표시)
2. 공식 기준으로 불충족이 하나라도 있으면 → **제외**
3. **미확인이 하나라도 있으면 → 확인 필요** (절대 추천으로 올리지 않는다)
4. 전부 충족 → **추천**

조건마다 **근거·출처·기준일**을 함께 들고 다니며 화면에 그대로 보여준다.

### 두 가지 안전장치

**1. 샘플 기준은 적격을 확정할 수 없다.**
HOME RADAR 가 가진 소득·자산 수치는 오픈소스 샘플 룰에서 온 어림값이다.
`Check` 는 `official=False` 인 근거가 '충족'이나 '불충족'을 만들려 하면
**구조적으로 '미확인'으로 내려앉힌다.** 샘플 규칙만 보고 적격·부적격을
확정하는 일이 코드 차원에서 불가능하다. 화면에는 `샘플 기준` 배지가 붙는다.

**2. 정보가 없으면 미확인이다.** 비어 있는 입력을 충족으로 보지 않는다.
그래서 자료가 부족하면 추천까지 올라가지 않는다.

이 두 가지 결과로 **공공분양·공공임대는 현재 구조상 '확인 필요'에 머문다.**
소득·자산 공식 기준이 없기 때문이고, 의도된 동작이다.
민영분양·무순위·오피스텔·민간임대는 조건이 다 차면 추천까지 간다.

### '충족'으로 인정하는 임계값

공고마다 기준이 다른 항목은 **어떤 기준이든 통과하는 선**을 넘었을 때만 충족으로 본다.

| 조건 | 충족 기준 | 근거 |
|---|---|---|
| 거주 요건 | 해당 지역 거주 **24개월** 이상 | 공고별 요건이 6~24개월 |
| 청약통장 가입기간 | **24개월** 이상 | 수도권 1순위 |
| 청약통장 납입횟수 | **24회** 이상 | 수도권 공공분양 1순위 |

무순위/잔여세대는 거주지역·무주택 요건이 개정을 거치며 여러 번 바뀌어
현재 기준을 코드로 단정하지 않고 공고문 확인으로 넘긴다.

### '확실히 통과하는 임계값'만 충족으로 본다

공고마다 기준이 다른 항목은 **어떤 기준이든 통과하는 선**을 넘었을 때만 충족이다.

| 조건 | 충족 기준 | 근거 |
|---|---|---|
| 청약통장 가입기간 | **24개월** 이상 | 수도권 1순위 (주택공급에 관한 규칙) |
| 청약통장 납입횟수 | **24회** 이상 | 수도권 공공분양 1순위 |

이 방식을 쓸 수 있는 건 **요건의 상한이 규정 수준으로 정해진 항목**뿐이다.
다른 유형들의 값을 일반화해서 만들면 안 된다 — 아래 두 사례가 그래서 틀렸다.

**자동차가액**: 한때 "확인된 유형이 모두 4,542만원이니 그 아래면 통과"로
충족을 줬다. 그런데 우리 데이터 안에 **대학생 행복주택의 '무차량'(0원)** 이라는
더 엄격한 반례가 있다. 기준을 모르는 유형이 4,542만원 이상이라고 단정할 수 없다.
→ 기준을 확인하지 못한 7개 유형(청년안심주택·고령자 행복주택·영구임대·
신혼희망타운·기존주택전세임대·뉴:홈 나눔/선택형)은 **'확인 필요'** 로 둔다.

**거주 요건**: 자격 조건으로 다루고 있었는데, [마이홈 국민임대 페이지](https://www.myhome.go.kr/hws/portal/cont/selectNationalRentalHouseView.do)
확인 결과 **자격이 아니라 선정순위·가점 요소**다(연속 거주 5년 3점·3년 2점·
1년 1점). 수도권 투기과열지구의 2년도 '우선공급' 요건이다.
→ `순위정보`로 분류해 **등급에 영향을 주지 않게** 했다. 자격이 아닌 것을
확정할 수 없다는 이유로 공고 38건이 '확인 필요'에 갇혀 있었다.

### 요건이 없는 것과 요건을 확인하지 못한 것은 다르다

소득·자산 검사를 만들지 않는 유형(무순위·민영 일반공급)은 **왜 없는지**를
출처와 함께 밝힌다. 공식 출처로 확인되지 않았으면 '확인 필요'를 만든다.

무순위는 [청약홈 무순위/잔여세대 안내](https://www.applyhome.co.kr/ar/ara/selectSubscrptIntroRemndrHshldView.do)로
확인했다 — 신청자격은 **"무주택세대구성원인 성년자"**(본인만이 아니다),
청약통장 사용여부 **X**, 소득·자산은 자격 요건에 열거되지 않음,
거주지역은 시·군·구가 정하는 기준(단지별).

**마이홈 표를 그대로 쓰면 1인 가구가 20% 틀린다.** 마이홈의 "100%" 열은
1·2인 가구 완화가 이미 반영된 값(1인 4,576,036 = 3,813,363 × 1.2)이라,
기저 소득표와 완화율(1인 +20%p, 2인 +10%p)을 **분리 저장**했다.
마이홈이 게시한 7개 가구원수 값을 전부 재현하는지 회귀 테스트로 고정했다.

### 소득을 합산해 '소득 인정액'이라 부르지 않는다

근로소득과 사업소득은 **인정 방식이 다르다**(사업소득은 종합소득세 신고 기준).
그래서 두 값을 합쳐 '소득 인정액'이라고 부르지 않는다.

- **근로소득만** 있으면 공식 기준과 비교해 충족/불충족을 낸다
- **사업소득이 있으면** 합산값을 참고로 보여주고 해당 조건은 **'확인 필요'**
- 합산 범위는 기준의 `scope_mode` 로 가른다 (본인 / 본인+부모 / 세대).
  미혼이면 배우자 소득을 섞지 않는다

### 맞벌이 · 배우자 소득

신혼 유형은 외벌이와 맞벌이 한도가 다르다(행복주택 100/120, 신혼희망타운 130/200).

| 입력 | 판정 |
|---|---|
| 배우자 소득 미입력 | **확인 필요** — 배우자 소득이 더해지면 넘을 수 있다 |
| 배우자 소득 **0** | 외벌이 확정 → 낮은 한도로 판정 |
| 배우자 소득 입력 | 맞벌이 확정 → 높은 한도로 합산 판정 |
| 배우자 **사업소득** 있음 | **확인 필요** (인정 방식 다름) |

**불충족은 배우자 소득 없이도 확정한다** — 본인 소득만으로 이미 상한을 넘었으면
배우자 소득을 더해도 결론이 바뀌지 않는다.

### 부동산가액

특별공급과 뉴:홈 일반형은 총자산이 아니라 **부동산가액**만 본다(2026년 2억 1,550만원).
`부동산가액`을 입력하면 바로 판정하고, 비워 두면 '총자산 전체가 한도 이하'일 때만
충족을 확정한다 (그 밖에는 확인 필요).

## 알림

| 알림 | 기준 |
|---|---|
| 새 공고 | 오늘 처음 관측 — **단, 수집원별 최초 배치(baseline)는 제외** |
| 마감 임박 | 접수 마감 N일 이내 (기본 3일) |
| 접수 시작 | 접수 시작 N일 이내 |
| 오늘 일정 | 오늘 접수 시작·마감·일정이 있는 공고 |
| 공고 변경 | 추적 필드가 바뀐 공고 |

**baseline**: 공고에 게시일이 항상 붙어 있지 않아 '우리가 처음 본 날'을 신규 기준으로
쓴다. 그러면 첫 수집 날에 전부 신규로 잡히고, 나중에 수집원을 하나 추가하면
그 수집원 공고가 전부 신규로 쏟아진다. 그래서 **수집원마다 첫 배치를 baseline 으로
찍어 신규에서 뺀다.** 그 다음 수집부터 들어온 공고만 신규로 센다.

모든 날짜 계산은 **KST(UTC+9)** 로 한다 (`util.today_kst`). UTC 로 계산하면 D-day 가
하루 밀린다 — 회귀 테스트로 고정해 뒀다.

알림 대상은 추천·확인 중 마감되지 않은 공고다. 자동 알림 발송은 **승인 전 붙이지 않았다.**

## 화면

모바일 우선으로 짰다. 640px 에서 2~5열로, 1180px 에서 폭이 고정된다.
다크 모드와 노치 safe-area 를 따른다.

- **통계 카드** — 추천/확인/제외/관심 건수 + 비율 바. 누르면 그 탭으로 걸러진다
- **수집원 칩** — 수집원별 마지막 성공 시각·건수, 막혔으면 그 이유
- **알림 카드 5개** — 누르면 해당 공고만 보인다
- **보기 전환** — 목록 / 캘린더(월) / 타임라인(앞으로 14일)
- **필터** — 지역, 공급유형, 단계, 검색, 태그 칩(청년·신혼부부·무순위…)
- **공고 상세** — 카드를 누르면 단지별·주택형별 공급정보 표
  (전용·공급면적, 세대수, 보증금·월임대료·분양가). 매입임대는 호별 주소·층 목록.
  제공되지 않는 항목은 열을 숨기고 무엇이 없는지 알려준다

### 단계(phase)가 말하는 것

| 단계 | 뜻 |
|---|---|
| 예정 | 접수 시작일을 알고, 아직 시작 전 |
| 접수중 | 접수 시작일을 알고, 기간 안 |
| **마감전(시작일 미상)** | 마감 전이지만 **시작일을 모른다** — 접수중이라고 단정하지 않는다 |
| 발표대기 | 접수는 끝났고 당첨 발표 전 |
| 마감 / 미정 | 접수 종료 / 일정 정보 없음 |

LH 는 상세 API 가 승인되지 않으면 마감일만 오므로 대부분 '마감전(시작일 미상)'이다.
'접수중'으로 찍으면 아직 시작하지 않은 공고까지 접수중으로 보여 주게 된다.
- **공고 카드** — 접수 시작/마감 D-day를 **따로** 표시, 공급금액(억/만원), 공급면적,
  규모, 주소, 조건별 충족/미확인/불충족과 그 근거·출처, 모집공고문·신청 링크
- **북마크** — 별표로 관심 공고 저장 (`data/bookmarks.json`)

금액은 서버가 만든 문자열이 아니라 **숫자에서 화면이 직접 포맷**한다. 캐시에 오래된
형식이 남아 있어도 표시가 틀어지지 않는다.

### 외부 UI 라이브러리를 쓰지 않은 이유

검증된 캘린더/차트 라이브러리(FullCalendar, Chart.js 등)를 검토했지만 넣지 않았다.
(1) 로컬·오프라인에서 돌아야 하고, (2) 빌드 과정 없이 단일 HTML 로 유지하는 쪽이
고치기 쉽고, (3) 필요한 건 월 그리드와 14일 타임라인뿐이라 수백 KB 의 의존성과
라이선스 검토를 들일 값이 없었다. 바꿀 만한 이유가 생기면 프런트만 교체하면 된다
— 백엔드가 JSON API 라 영향이 없다.

## 규칙 버전 관리

`rules.RULES_VERSION` (현재 `2026.10.30-2`) 을 판정 결과마다 같이 내려보낸다.
기준을 바꾸면 버전을 올리고 `tests/test_core.py` 에 회귀 테스트를 추가한다.

테스트에는 다음 불변식이 고정돼 있다.

- 샘플 기준은 충족·불충족을 만들 수 없다
- 미확인이 있으면 추천하지 않는다
- 공공분양은 샘플 규칙만으로 추천되지 않는다
- 첫 수집·새 수집원의 첫 배치는 신규가 아니다
- D-day 는 KST 기준이고 접수 시작/마감이 따로 계산된다
- 모든 제외에는 사유가 있다

## 외부 배포 — 아이폰에서 쓰기

PC 없이 폰으로 보려면 HTTPS 주소가 필요하다. 그 순간 생년·소득·자산이
인터넷에 놓이므로, 배포 모드에서는 **로그인이 기본**이고 끌 수 없게 해 뒀다.

### 한 번만 하는 준비

1. GitHub 비공개 저장소를 만들고 `main` 브랜치를 올린다.
2. [Render](https://render.com) 에 GitHub 로 로그인 → **New → Blueprint** →
   그 저장소를 고른다. `render.yaml` 을 읽어 서비스가 자동으로 만들어진다.
3. 대시보드 **Environment** 에 아래 값을 넣는다 (`sync: false` 항목들).

| 환경변수 | 값 | 없으면 |
|---|---|---|
| `APP_PASSWORD` | 길고 추측 어려운 비밀번호 | **서버가 뜨지 않는다** |
| `CRON_TOKEN` | 아무 긴 임의 문자열 | 주기 수집 입구가 닫힌다 |
| `LH_API_KEY` | 일반 인증키(Decoding) | LH 수집만 건너뛴다 |
| `APPLYHOME_API_KEY` | 일반 인증키(Decoding) | 청약홈 API 수집만 건너뛴다 |
| `PROFILE_JSON` | 내 조건 한 줄 JSON | 기본값으로 시작한다 |

4. GitHub 저장소 **Settings → Secrets → Actions** 에
   `APP_URL`(배포 주소)과 `CRON_TOKEN`(3번과 같은 값)을 넣는다.
   `.github/workflows/refresh.yml` 이 매시 공고를 갱신한다.

### 검증

```powershell
python scripts/verify_deploy.py https://내주소.onrender.com `
    --password <APP_PASSWORD> --cron-token <CRON_TOKEN>
```

로그인 전 차단, 보안 헤더, PWA 파일, 크론 입구까지 한 번에 확인한다.

### 무료 플랜에서 알고 있어야 할 것

- **15분간 접속이 없으면 잠든다.** 다음 접속은 깨우는 데 30~60초.
  크론이 매시 두드려서 낮 동안은 대체로 깨어 있다.
- **영구 디스크가 없다.** 재배포·재시작하면 `data/` 와 `profile.json` 이 사라진다.
  - 공고 캐시 → 기동 직후 자동으로 다시 수집한다 (손댈 것 없음).
  - 내 조건 → 화면의 **`PROFILE_JSON` 값 복사** 버튼으로 얻은 값을
    대시보드 환경변수에 넣어 두면 그 값으로 복원된다.
- 월 $7 Starter 로 올려 영구 디스크를 붙이면 둘 다 없어지는 문제다.
  `render.yaml` 의 `disk:` 주석을 풀고 `DATA_DIR=/var/data` 만 주면 끝이고,
  **코드는 한 줄도 바꾸지 않는다.**

### 배포 모드에서 더 붙는 보호

| 보호 | 어떻게 |
|---|---|
| 로그인 | `APP_PASSWORD` + HMAC 서명 세션 쿠키 (HttpOnly·SameSite=lax·Secure) |
| 비밀번호 없이 기동 금지 | `HR_REQUIRE_AUTH=1` — 없으면 **기동 실패** |
| 추측 차단 | IP당 10회 실패 시 10분 잠금 |
| 외부 유출 경로 차단 | CSP `connect-src 'self'` — 외부 호스트 접속 자체가 막힌다 |
| 중간 캐시 금지 | 모든 개인정보 응답에 `Cache-Control: no-store` |
| 기기 캐시 금지 | 서비스워커가 `/api/*` 를 아예 건드리지 않는다 |
| 색인 거부 | `robots.txt` 전면 `Disallow: /` |
| 기타 | HSTS·nosniff·X-Frame-Options DENY·no-referrer, OpenAPI 문서 비활성화 |

### 아이폰 홈 화면에 설치

사파리로 주소를 열고 로그인 → 아래 **공유** → **홈 화면에 추가** → **추가**.
주소창 없이 앱처럼 열리고, 아이콘·앱 이름·시작 화면이 붙는다.
(크롬·파이어폭스에서는 설치 메뉴가 없다. **사파리로 열어야 한다.**)

## 남은 공백

사용자가 할 일: **없다.** 공공데이터포털 API 4종(청약홈 분양정보, LH 목록·
상세·공급정보)이 모두 승인·동작 중이다.

코드 쪽 공백 (전부 '확인 필요'로 안전하게 처리된다):

- [ ] **자동차가액 기준을 확인하지 못한 7개 유형** — 청년안심주택·고령자
      행복주택·영구임대·신혼희망타운·기존주택전세임대·뉴:홈 나눔/선택형.
      공식 페이지에 금액이 없어 차량 보유 시 '확인 필요'가 된다.

- [ ] **공공분양 일반공급 맞벌이 한도** — 같은 공식 페이지의 두 요약이 140%/200%로
      상충해 확정하지 못했다 (`dual_pct=None`)
- [ ] **뉴:홈 나눔·선택형 순자산 기준연도** — 금액(3억 6,200만원)은 확인했지만
      적용연도 표기가 없다
- [ ] **영구임대·기존주택전세임대 자산 금액** — 공식 페이지에 금액이 없어
      자산 비교 자체를 만들지 않는다
- [ ] **장기전세 지역 축** — 서울 6억 6,200만원 / 경기 4억 1,700만원인데
      기준 스키마에 지역 축이 없어 경기 하한 + '초과해도 확정 안 함'으로 뒀다
- [ ] 장기전세 85㎡ 초과 소득기준, 든든전세 (전세임대로 합쳐져 구분 불가)
- [ ] 뉴:홈 특별공급별 소득 %(청년 140% 등) — 기준 스키마에 특공 축이 없다
- [ ] 청약통장 납입인정금액 기반 순위 판정 (입력 항목은 이미 있다)
- [ ] 자동 알림(디스코드·텔레그램) — **승인 후**
- [ ] 외부 배포 — **승인 후**

법제처 『공공주택 특별법 시행규칙』 별표가 가장 권위 있는 출처인데
`law.go.kr` 이 JS 렌더링이라 본문을 받지 못했다. 필요하면 국가법령정보
OpenAPI(별도 키)가 유일한 경로다.
