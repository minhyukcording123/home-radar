# HOME RADAR

공식 청약 공고를 자동으로 모아, 내 조건(나이·소득·자산·무주택·청약통장)으로
**추천 / 확인 / 제외** 로 갈라 보여주는 개인용 웹앱.
매일 새로 올라온 공고와 접수 마감 임박 공고를 같이 알려준다.

로컬 전용이다. 원격 저장소와 외부 배포는 아직 붙이지 않았다.

---

## 빠른 실행

```powershell
cd C:\minkkk\home-radar

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 1) 공고 수집 (첫 실행은 상세까지 긁어서 1~2분 걸린다)
.\.venv\Scripts\python.exe -m app refresh

# 2) 웹앱 실행
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8777
```

브라우저에서 <http://127.0.0.1:8777> 을 열고 우측 상단 **내 조건** 에 본인 정보를
넣으면 바로 판정이 다시 계산된다. 수집은 **새로고침** 버튼으로도 돌린다.

터미널에서만 보고 싶으면:

```powershell
.\.venv\Scripts\python.exe -m app show
```

## 데이터는 어디서 오는가

**청약홈(한국부동산원) 공개 화면이 쓰는 엔드포인트를 그대로 호출한다. API 키가 필요 없다.**

| 경로 | 내용 | 키 |
|---|---|---|
| 청약일정 캘린더 | 단지명·지역·접수 유형·접수일 | 불필요 |
| 공고 상세 | 공급위치·공급규모·발표일·공급금액·모집공고문 PDF | 불필요 |

공공데이터포털의 **공식 청약홈 오픈API**(`api.odcloud.kr`, 서비스 15098547)도 있지만
활용신청 후 받은 키가 없으면 `401` 이 떨어진다. 그래서 1차 수집원으로는 쓰지 않았다.
키를 발급받으면 보강 경로로 붙일 수 있다 — 아래 "다음 단계" 참고.

수집 범위는 기본 **지난달 ~ 6개월 뒤** 다. `python -m app refresh --back 2 --ahead 9` 로 바꾼다.

## 판정 방식

원칙은 기반 오픈소스(cheongyak-auto)의 판단을 그대로 따른다.

> 공고 목록에는 제목·유형 정도만 있어서 세부 소득·자산 기준은 알 수 없다.
> 그래서 **구조적으로 확실히 안 되는 것만 제외**하고, 애매하면 '확인'으로 살린다.
> (잘못 걸러서 놓치는 손해 > 알림 하나 더 받는 손해)

| 분류 | 의미 |
|---|---|
| **추천** | 내 조건에 구조적으로 맞는 공고 |
| **확인** | 가능성은 있지만 공고문을 봐야 하는 공고 |
| **제외** | 구조적으로 지원이 안 되는 공고. **왜 빠졌는지 확인할 수 있게 숨기지 않고 보여준다** |

### 제외가 되는 경우 (구조적으로 확실한 것만)

- 관심 지역·관심 유형이 아님
- 유주택인데 분양·공공임대 공고
- 청약통장이 없는데 통장을 쓰는 공고
- 대상 계층 불일치 — 청년(만 19~39) / 고령자(만 65+) / 신혼·신생아 / 다자녀 / 장애인 / 수급자 / 대학생
- 모집이 아닌 후속 안내(당첨자 발표, 서류 제출, 계약 안내)는 '무시'로 목록에서 빠진다

### 소득·자산은 제외 근거로 쓰지 않는다

공고별 실제 기준이 항상 우선하기 때문이다. 대신 **신호등**으로 계산해서 보여준다.

- 내 월소득이 도시근로자 월평균소득의 몇 % 인지 (가구원 수 기준)
- 특별공급 상한(신혼부부 140% / 생애최초 160%) 대비 `여유 / 경계 / 초과`
- 총자산·자동차가액이 공공 유형 기준(약 3.62억 / 3,900만원)을 넘는지

상한을 넘으면 **추천을 '확인'으로 낮추고 사유를 남긴다.** 제외하지는 않는다.
일반공급·추첨제는 소득 요건이 없는 경우가 많아서다.

## 알림

웹앱 상단에 세 칸으로 뜬다.

| 알림 | 기준 |
|---|---|
| 오늘 새로 올라온 공고 | `data/seen.json` 에 **처음 관측된 날**이 오늘인 공고 |
| 접수 마감 N일 이내 | 내 조건의 `마감 며칠 전부터 알릴까` (기본 3일) |
| 오늘이 접수일 | 일정 중 오늘 날짜가 있는 공고 |

공고에 '언제 게시됐는지'가 항상 붙어 있지 않아서, **우리가 처음 본 날**을 새 공고 기준으로 삼는다.
그래서 맨 처음 수집한 날은 모든 공고가 '새 공고'로 잡힌다 — 다음 날부터 정상 동작한다.

알림 대상은 **추천·확인 중 마감되지 않은 공고**다. 제외된 공고는 알리지 않는다.

### 매일 자동 수집

`scripts\daily.ps1` 을 Windows 작업 스케줄러에 등록하면 된다.
등록 명령은 그 파일 맨 위 주석에 있다. (등록은 시스템 설정을 바꾸므로 직접 실행해야 한다.)

## 구조

```
app/
  main.py                FastAPI — 화면 + JSON API
  __main__.py            CLI (refresh / show) — 스케줄러가 쓴다
  collect.py             수집 → 보강 → 판정 → 알림 파이프라인
  eligibility.py         추천/확인/제외 판정 엔진
  models.py              Notice 공통 레코드, 마감 추정
  profile.py             내 조건 스키마 / 저장
  rules.py               소득·자산 기준 데이터
  store.py               JSON 캐시 + '처음 본 날' 기록
  util.py                날짜 파싱, 시도 정규화, HTTP
  sources/
    applyhome_cal.py     청약일정 캘린더 (1차 수집원)
    applyhome_detail.py  공고 상세 보강
  web/index.html         단일 파일 UI (빌드 과정 없음)
tests/test_core.py       네트워크 없이 도는 회귀 테스트 38개
scripts/daily.ps1        매일 수집용
_reference/              참고용으로 클론한 외부 저장소 (우리 코드 아님, gitignore)
```

**수집과 판정을 분리했다.** 수집(`refresh`)은 네트워크를 수십 번 때리니 캐시에 넣고,
판정(`build_view`)은 조회할 때마다 로컬에서 다시 돈다.
그래서 내 조건을 바꿔도 다시 긁지 않고 즉시 결과가 바뀐다.

### API

| 엔드포인트 | 설명 |
|---|---|
| `GET /api/view?include_closed=` | 버킷 + 알림 + 통계 |
| `GET /api/profile` / `PUT /api/profile` | 내 조건 조회·저장 |
| `POST /api/refresh` → `GET /api/refresh/status` | 백그라운드 수집 |
| `GET /api/detail?house_manage_no=&pblanc_no=&house_secd=` | 공고 상세 (캐시 우선) |
| `GET /api/health` | 캐시 상태 |
